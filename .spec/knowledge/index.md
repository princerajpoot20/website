## What this project does

The AsyncAPI website (asyncapi.com) — a Next.js MDX site that hosts docs, the blog, the tools directory, community pages, and case studies. Content is a mix of committed MDX/JSON and generated JSON built from external sources (GitHub, Google Calendar, YouTube, Kit) at CI time and at each build. Deployed to Netlify with a mix of static pages, edge functions, and background functions.

---

## Tech stack

- Next.js 15 (Pages Router) + React 18 + TypeScript
- Tailwind CSS + custom design tokens
- MDX for docs and blog
- Algolia for search, Netlify for hosting, edge and background functions
- Jest (unit + scripts), Cypress (E2E), Deno (edge tests)
- `next-i18next` for translations
- `@octokit/graphql` for GitHub GraphQL calls
- `googleapis` for Google Calendar / YouTube
- `npm` at root

## Cross-cutting architecture notes

- **Config JSON files** in `config/` are the source of truth for most content assembled at build time. Some are human-authored (`tools-manual.json`, `MAINTAINERS.json`, etc.), some are generated by workflows and committed via bot PR (`tools*.json`, `all-tags.json`, `meetings.json`, `newsroom_videos.json`).
- **`dashboard.json`** is an exception — lives at the repo root, not under `config/`.
- **Bot-opened PRs** target branches with maintainer review as a safety layer. See `principles.mdc` and the workflows topics.
- **`scripts/`** hosts every build-time and workflow-invoked script. Each has a single entrypoint invoked via `npm run generate:*` or from `scripts/index.ts` at `next build` time.
- **Testing follows source layout** — every `scripts/X.ts` has `tests/X.test.ts`.
- **SSR / hydration** — Next.js Pages Router; guard `window` access and be careful with dynamic imports. See `frontend/ssr-and-hydration.md`.
